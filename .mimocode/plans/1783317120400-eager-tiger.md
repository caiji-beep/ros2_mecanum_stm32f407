# STM32 CAN OTA 代码走读笔记

## 目标
帮助理解 `src/stm32_can_ota/` 这个 AI 生成的 OTA 骨架框架。

## 包结构

```
stm32_can_ota/
├── CMakeLists.txt
├── package.xml
├── config/ota.yaml              # ROS2 参数配置
├── launch/stm32_can_ota.launch.py  # ROS2 launch 文件
├── msg/OtaStatus.msg            # 状态消息定义
├── srv/StartOta.srv             # 启动 OTA 的服务定义
├── scripts/download_firmware.py # 固件下载辅助脚本
├── include/stm32_can_ota/       # 头文件
│   ├── can_frame.hpp            # CAN 帧数据结构
│   ├── can_transport.hpp        # SocketCAN 通信
│   ├── crc16.hpp                # CRC16 校验
│   ├── crc32.hpp                # CRC32 校验
│   ├── firmware_image.hpp       # 固件二进制镜像
│   ├── firmware_package.hpp     # 固件包（含 manifest）
│   ├── ota_client.hpp           # OTA 核心客户端
│   ├── ota_error.hpp            # 错误码枚举
│   ├── ota_protocol.hpp         # OTA 协议帧构建
│   ├── ota_state.hpp            # 状态机枚举
│   └── stm32_ota_node.hpp       # ROS2 节点
└── src/                         # 实现
    ├── main.cpp                 # 入口
    ├── can_transport.cpp        # SocketCAN 实现
    ├── crc16.cpp
    ├── crc32.cpp
    ├── firmware_image.cpp
    ├── firmware_package.cpp
    ├── ota_client.cpp
    ├── ota_protocol.cpp
    └── stm32_ota_node.cpp
```

## 调用链

外部调用者 → Stm32OtaNode (ROS2 service) → OtaClient (状态机) → OtaProtocol (帧构建) + FirmwarePackage (固件加载) → CanTransport (CAN IO) → STM32 Bootloader

## 已实现 vs 未实现

### 已实现：
- CAN 帧收发（SocketCAN，非阻塞 IO，超时等待）
- OTA 协议帧构建（SYNC/GET_CAPABILITY/START/BLOCK_BEGIN/DATA/END）
- 固件文件加载 + CRC32 计算
- ROS2 节点 + Service/Topic 接口
- 参数化配置（CAN ID、超时、block_size 等）
- 固件下载脚本（SHA256 校验 + 符号链接管理）

### 未实现（骨架）：
- OtaClient::start() 中真正的传输流程（dry_run 之外直接返回 not_implemented）
- SYNC → GET_CAPABILITY → START → DATA → END 的完整握手
- ACK/NACK 等待与重传
- Block 级别进度上报
- Manifest 多文件包加载
