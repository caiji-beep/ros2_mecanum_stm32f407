# SYSTEM（stm32f407 分支）

`SYSTEM` 目录是下位机工程的系统支撑层，用于承载 **与业务无关、但所有任务都依赖的公共基础能力**。它不是某个单独外设驱动，也不是某个单独任务，而是整个系统稳定运行的底层支撑。

---

## 1. 目录结构

当前目录包含：

```text
SYSTEM/
├── delay/
├── sys/
├── usart/
├── SPL_Delay.c / SPL_Delay.h
├── Timer.c / Timer.h
├── retarget_uart.c / retarget_uart.h
├── robot_state.c / robot_state.h
└── watchdog.c / watchdog.h
```

---

## 2. 模块说明

### `delay/` 与 `SPL_Delay.*`

延时相关模块。

主要用于：

- 基础延时
- 某些初始化过程中的时序等待
- 对某些外设初始化提供时间支撑

### `sys/`

通常用于系统级配置与底层公共定义。

### `usart/`

底层串口系统支撑目录，通常与 `retarget_uart.*` 或更高层 UART 模块配合使用。

### `Timer.c / Timer.h`

定时器支撑模块。

可用于：

- 周期性调度辅助
- 时间戳
- 控制周期基准
- 某些系统级测时逻辑

### `retarget_uart.c / retarget_uart.h`

串口重定向模块。

常用于把 `printf` 等调试输出重定向到串口，提升调试效率。

### `robot_state.c / robot_state.h`

机器人状态管理模块。

一般负责：

- 系统状态变量维护
- 模式切换标志管理
- 运行状态汇总
- 供各任务读取当前机器人状态

### `watchdog.c / watchdog.h`

看门狗模块。

该项目已有软件看门狗和硬件看门狗方向的更新记录，因此这个模块对系统可靠性非常重要。

---

## 3. 目录定位

可以把 `SYSTEM` 看成下位机工程的“公共底座”：

- `HARDWARE` 依赖它提供一些底层公共能力
- `MyTasks` 依赖它提供状态、时间、调试和系统安全能力

---

## 4. 为什么这个目录重要

很多学生项目只关注“驱动能跑、任务能跑”，但真正系统化的嵌入式工程，必须把：

- 时间基准
- 状态管理
- 调试输出
- 安全监测

这些公共能力独立出来。

`SYSTEM` 正是在做这件事。

---

## 5. 维护建议

### 保持系统模块通用性

`SYSTEM` 层尽量不要写太多业务细节。

### 把状态定义集中管理

不要让多个任务随意定义重复状态变量。

### 看门狗逻辑必须配套说明

建议在 README 或代码注释中说明：

- 谁喂狗
- 多久超时
- 复位条件是什么
