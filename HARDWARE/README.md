# HARDWARE（stm32f407 分支）

`HARDWARE` 目录用于存放 **底层外设驱动**，是下位机固件中最贴近具体硬件的部分。这里的代码不直接负责高层任务调度，而是提供“能用的硬件接口”。

---

## 1. 目录结构

根据当前工程内容，`HARDWARE/` 目录包括：

```text
HARDWARE/
├── Can.c / Can.h
├── Encoder.c / Encoder.h
├── IMU_Icm20948.c / IMU_Icm20948.h
└── （其余外设相关文件可能继续扩展）
```

> 仓库目录页还显示该目录承担 OLED、PWM、蜂鸣器等外设方向；若后续文件补充，请同步更新本 README。

## 2. 模块说明

### `Can.c / Can.h`

CAN 通信驱动模块。

典型职责包括：

- CAN 外设初始化
- 波特率配置
- 发送与接收接口
- 中断或轮询处理
- 与其他控制板进行总线通信

在本项目中，它适合用于：

- 与其他 STM32 控制板通信
- 扩展底盘内部板间通信
- 采集其他模块发来的 IMU / 状态信息

---

### `Encoder.c / Encoder.h`

编码器采集模块。

典型职责包括：

- 定时器编码器模式配置
- 脉冲计数读取
- 增量值计算
- 速度估算基础支持

它是轮速反馈、里程计估计和闭环控制的底层数据来源之一。

---

### `IMU_Icm20948.c / IMU_Icm20948.h`

ICM20948 IMU 驱动模块。

典型职责包括：

- 传感器初始化
- I2C 通信读写
- 加速度/角速度/姿态相关原始数据获取
- 上层任务调用接口

该模块可为机器人提供：

- 姿态辅助估计
- 运动状态检测
- 与导航系统相关的惯性信息来源

---

## 3. 目录定位

`HARDWARE` 目录关注的是“外设驱动能不能工作”，而不是“任务逻辑怎么调度”。

可以这样理解：

- `HARDWARE`：会不会驱动
- `MyTasks`：什么时候用驱动、怎么调度驱动
- `SYSTEM`：给驱动和任务提供系统支撑

---

## 4. 开发建议

### 4.1 保持接口层次清晰

建议每个外设模块都尽量统一以下结构：

- `Init()`：初始化
- `Read()/Write()`：基本访问
- `GetXxx()`：对上层输出清晰接口

### 4.2 避免在驱动层混入任务逻辑

`HARDWARE` 层不要写太多业务判断，否则后期难维护。

### 4.3 对硬件依赖做明确注释

例如：

- 使用哪个 USART / TIM / CAN / I2C
- 对应引脚是什么
- 时钟依赖是什么
