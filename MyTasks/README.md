# MyTasks（stm32f407 分支）

`MyTasks` 是本项目下位机工程的 **应用任务层**。如果说 `HARDWARE` 负责“驱动能用”，那么 `MyTasks` 负责“这些驱动在 FreeRTOS 下如何协同工作”。

---

## 1. 目录结构

当前目录包含：

```text
MyTasks/
├── CTRL.c / CTRL.h
├── Display.c / Display.h
├── IMU.c / IMU.h
├── Telemetry.c / Telemetry.h
└── Uart.c / Uart.h
```

---

## 2. 各任务模块说明

### `CTRL.c / CTRL.h`

控制任务模块。

通常是整个下位机最关键的业务任务之一，可能承担：

- 速度命令处理
- 电机控制输出
- 死区补偿
- 状态机联动
- 运行模式切换

如果下位机要真正驱动底盘运动，这里通常是核心逻辑入口之一。

---

### `Display.c / Display.h`

显示任务模块。

一般负责：

- OLED 或屏幕信息更新
- 模式显示
- 运行状态展示
- 调试信息显示
- 页面切换逻辑

这部分对调试非常实用，因为它提供了不依赖上位机的本地状态可视化能力。

---

### `IMU.c / IMU.h`

惯性数据处理任务模块。

一般负责：

- 调用底层 IMU 驱动
- 周期性读取传感器数据
- 做简单滤波或数据整理
- 向其他任务发布姿态/角速度信息

---

### `Telemetry.c / Telemetry.h`

遥测任务模块。

一般负责：

- 状态数据整理
- 向上位机上报关键数据
- 调试输出
- 运行状态监控

对于机器人下位机来说，这一层非常重要，因为它决定了上位机能看到多少“底层真实状态”。

---

### `Uart.c / Uart.h`

串口任务模块。

一般负责：

- 串口接收任务
- 串口发送任务
- 协议解析
- 与 ROS2 上位机或其他主控的串口通信

这部分与 ROS2 `mecanum_hw_interface` 分支之间存在直接对应关系。

---

## 3. 目录定位

`MyTasks` 的核心价值在于：

- 将功能拆成多个任务
- 利用 RTOS 做并发调度
- 让控制、显示、通信、遥测彼此解耦

这样系统更容易做到：

- 实时性更稳定
- 模块更清晰
- 问题更容易排查

---

## 4. 典型协作关系

可以把这些任务理解为：

- `CTRL`：控制执行核心
- `IMU`：状态感知输入
- `Uart`：与上位机通信
- `Telemetry`：状态上报
- `Display`：本地显示

它们共同组成下位机的业务层。

---

## 5. 开发建议

### 每个任务只做一类事

不要让一个任务同时做控制、显示、通信，否则难维护。

### 尽量通过共享数据结构或消息机制通信

避免不同任务直接强耦合调用。

### 对任务周期和优先级做明确说明

这对后期排查实时性问题很重要。
